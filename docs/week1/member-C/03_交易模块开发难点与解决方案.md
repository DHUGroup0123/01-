\# 交易模块开发难点与解决思路（成员C）



1\. \*\*高并发下的超卖问题\*\*

   \* \*\*难点\*\*：用户同时下单时，如果不加控制会导致库存扣减为负数。

   \* \*\*解决思路\*\*：下周在 Mapper 层的 SQL 语句中，使用 `UPDATE goods SET stock = stock - #{count} WHERE goods\\\_id = #{id} AND stock >= #{count}`。通过数据库行锁保证库存不会被超卖，Service 层判断返回的受影响行数是否大于 0。



2\. \*\*订单状态流转的强校验\*\*

   \* \*\*难点\*\*：状态机复杂，容易出现非法越权操作（如“待支付”直接“出库”）。

   \* \*\*解决思路\*\*：已提前定义好枚举类。下周在 Service 层（如 `checkDone`、`checkOut`）中，必须先查出订单当前状态，严格比对前置条件，不符合直接抛出 `ServiceException` 异常并阻断事务。



3\. \*\*购物车数据合并\*\*

   \* \*\*难点\*\*：用户多次添加同一件商品，需要将数量累加，而不是新增一条记录。

   \* \*\*解决思路\*\*：先根据 `user\\\_id` 和 `goods\\\_id` 查询是否已有记录。如果有，获取原记录并更新数量；如果没有，则执行 Insert。并且更新数量时要判断总数不能超过上限（5件）。
