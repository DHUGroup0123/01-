## 公共返回与鉴权

统一结构：`{"code":200,"message":"操作成功","data":{}}`，无数据时 data 为 null。失败时 HTTP 状态与 code 对齐：400 参数错误、401 未登录、403 无权限、404 不存在、409 重复或库存/状态冲突、503 数据库暂不可用。后续分页结构为 data.list / page / pageSize / total。

Session 用户键 `mallUser`，内容为 `SessionUser(userId, loginName, nickname)`，位于 memberA.user.dto；管理员单独使用 adminUser，验证码键 mallCaptcha。Session 超时30分钟，cookie HttpOnly、SameSite=Lax。第二周登录成功必须更换 Session ID，退出销毁会话；验证码一次有效、校验后销毁并设定过期时间。密码不进入 Session、JSON 和日志。

用户与管理员鉴权分离。A 负责统一用户拦截器，但 C 的服务层仍必须用当前 Session userId 校验购物车、订单与地址归属，禁止信任前端传入 userId。B 负责管理员拦截器。Cookie 会话的写操作第二周必须增加 CSRF token 验证，前端 AJAX 同时提交 token。

## A 与 B 的商品约定

- 商品字段：productId、categoryId、productName、summary、coverUrl、detailHtml、originalPrice、sellingPrice、stock、sellStatus。
- ID 在后续业务 API 中输出十进制字符串，避免 JavaScript 大整数精度损失。Java 使用 Long。
- 价格 JSON 使用两位小数字符串；Java BigDecimal，不经 double 计算。第一周 ProductPreview 只用于服务端模板，不是冻结的公开商品API。
- sellStatus=1 上架、0 下架；不照搬参考项目0上架。下架不显示在公开列表和详情，不允许新下单。
- 分类为三级，parentId=null 代表根；商品挂三级分类。分类逻辑删除前检查有效子分类与商品引用。
- sort 枚举 latest / priceAsc / priceDesc，服务端白名单选择SQL；keyword≤50字符，page≥1，pageSize默认12最大50。SQL全部参数化，不能拼接用户输入排序字段。
- 本周 A 的 EnvironmentMapper 只是少量只读启动验证，第二周商品写入Mapper/实体由B主维护。

## A 与 C 的用户和地址约定

- C 从 SessionKeys.MALL_USER 读取 SessionUser；未登录返回401。
- 地址按 userId 查询，C 以 `address_id=? AND user_id=?` 验证后保存订单地址快照，不能接收浏览器指定完整地址而跳过归属检查。
- B 禁用用户后，受保护请求需重新核对用户状态，不能只依赖旧 Session。

## B 与 C 的金额库存与状态约定

- 总额由服务端读取商品价格计算，忽略前端单价、金额和状态字段。
- 下单原子扣库存：`UPDATE product SET stock=stock-?, updated_at=CURRENT_TIMESTAMP WHERE product_id=? AND stock>=? AND sell_status=1`；影响行数不为1则回滚整单。
- 创建订单、快照明细、扣库存和清购物车在一个事务。后续用幂等请求号防止重复提交，方案由 C 在第二周补齐。
- 正常状态：0待支付 → 10已支付 → 20已配货 → 30已出库 → 40完成。
- 关闭状态：仅从0可到-10用户取消、-20超时关闭、-30商家关闭，关闭时一次性返还库存。第一版不处理已支付退款；已支付关闭需求必须另外协商。
- 支付演示仅允许0→10且payStatus由0→1；重复请求不重复产生副作用。payMethod=DEMO，不接真实支付。
- 用户确认收货只允许30→40。后台配货10→20，出库20→30。更新带当前状态条件，拒绝非法跳转。
