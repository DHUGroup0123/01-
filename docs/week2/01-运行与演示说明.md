# 01电商系统 第二周运行与演示说明

## 开发环境

沿用 Java17、Spring Boot4.0.8、MyBatis4.0.1、仓库Maven Wrapper3.10.0和MySQL8.0。IDEA Project SDK与Maven Runner JRE均设为17，运行原来的TeamWorkApplication。不要切回任务书初稿的Java8/Boot2.7。

## 无数据库密码的临时演示

```powershell
.\mvnw.cmd -B verify
.\scripts\Start-Demo.ps1
```

默认地址 http://localhost:28089/ 。demo显式使用H2，包含15件演示商品、3级分类、2张轮播及首页配置，可以直接测试搜索分页。H2中注册与修改的数据在应用关闭后清空，不能作为日常保存数据的方案。

没有固定测试账号或后台管理员密码。首次在浏览器注册自己的演示账号，验证码2分钟内有效、不区分大小写且仅能使用一次。失败后页面自动刷新验证码。

## MySQL 持久化运行

现有第一周mall_01库若已初始化，直接使用原连接即可，第二周不需要结构迁移。全新数据库先运行database/create-database.sql并配置本地环境变量：

```powershell
$env:DB_USERNAME='你的MySQL开发账号'
$securePassword=Read-Host 'MySQL密码' -AsSecureString
$pointer=[Runtime.InteropServices.Marshal]::SecureStringToBSTR($securePassword)
try { $env:DB_PASSWORD=[Runtime.InteropServices.Marshal]::PtrToStringBSTR($pointer) }
finally { [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($pointer) }
.\mvnw.cmd spring-boot:run '-Dspring-boot.run.profiles=init'
```

首次确认可启动后移除init，正常运行`.\mvnw.cmd spring-boot:run`。默认不执行SQL，旧账号资料地址保持在MySQL中。`DB_URL`可指定其他本机MySQL地址，`SERVER_PORT`可指定其他端口。

需要更多商品与轮播演示时，只在独立课程演示库中选择sample：

```powershell
.\mvnw.cmd spring-boot:run '-Dspring-boot.run.profiles=sample'
```

sample非破坏性补齐V001和第二周演示行，不覆盖既有同ID记录；它不保证与其他成员自编演示ID无冲突，因此不要在混有未知数据的库上盲目加载。第二周额外商品ID为101至112、轮播101至102、首页配置1001至1012。V001脚本没有改动；V002__mall_demo.sql不改变结构，也不登记新的结构版本。

## 成员 A 演示顺序

1. 打开首页：观察轮播切换、分类、热销、新品与推荐；点击轮播可进入对应搜索。
2. 点击注册，输入4至32位字母数字下划线账号、8至72位密码及验证码。确认密码一致后创建账号。
3. 登录：输入账号密码与新验证码，进入个人中心；错误验证码或密码应出现明确提示。
4. 修改昵称和手机号，点击保存；刷新页面确认资料保留。
5. 进入收货地址，新增两条，切换默认地址、编辑地址，确认只有一条默认；删除默认地址后检查自动选定剩余地址。
6. 进入全部商品，搜索“台灯”，选择分类与价格排序；清空关键词、每页6件，翻到第二页。
7. 点击商品查看价格、库存及说明；商品下架后通过原URL应返回404，不能继续作为上架商品展示。
8. 退出登录后，再访问/personal或/api/addresses，分别应跳转登录页或返回401。

页面中不接真实支付，没有购物车与订单写操作；交易联调留给第三周。

## 针对独立 MySQL 测试库执行14项集成测试

仅使用专门的空测试库，不能把测试URL指向开发数据或真实数据！测试会新增/删除测试用户与地址，并暂时修改演示商品、分类状态。先在MySQL建立mall_week2_tests空库，再设：

```powershell
$env:WEEK2_TEST_DB_URL='jdbc:mysql://localhost:3306/mall_week2_tests?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai'
$env:WEEK2_TEST_DB_DRIVER='com.mysql.cj.jdbc.Driver'
$env:WEEK2_TEST_DB_USER=$env:DB_USERNAME
$env:WEEK2_TEST_DB_PASSWORD=$env:DB_PASSWORD
.\mvnw.cmd -B '-Dtest=MemberAWeekTwoTests' test
Remove-Item Env:WEEK2_TEST_DB_URL,Env:WEEK2_TEST_DB_DRIVER,Env:WEEK2_TEST_DB_USER,Env:WEEK2_TEST_DB_PASSWORD -ErrorAction SilentlyContinue
```

默认verify使用独立H2测试库，不需要设置这些变量。MySQL测试复用demo的数据初始化，仅覆盖测试数据源；测试时的demo标志不代表真实驱动仍是H2，日志中的JDBC连接应为MySQL。

## 常见问题

- 401：先登录；退出、Session过期或用户记录不存在都会要求重新登录。
- 403页面凭证失效：刷新页面重新获取CSRF；登录成功后旧token自动失效。
- 403账号禁用：由B处理用户状态，用户不能自行解禁。
- 429：注册与登录共享每账号10次/5分钟、每IP60次/5分钟的单实例内存窗口，所有尝试都计数。
- 注册409：账号已存在；账号统一小写，因此大小写不作为不同账号。
- 地址404：不存在或不属于当前用户，不暴露他人地址是否真实存在。
- 无轮播/少量商品：普通init只使用第一周数据，可在独立演示库使用sample，或由B配置正式演示商品。
- 图片只支持本机/images或/uploads路径，非法或缺失图片使用本项目自绘占位图。
- 正式部署若启用HTTPS，应在部署配置中开启Session cookie Secure；当前本机HTTP开发环境未强制Secure。
